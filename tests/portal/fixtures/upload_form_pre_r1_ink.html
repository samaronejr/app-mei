{% load i18n %}{% comment %} The whole upload control, drawn on the vault page and again on the refusal page so that a client who was just refused can retry without navigating anywhere. Included WITHOUT `only`, exactly as `portal/partials/nav.html` is. That is not laziness about the convention: `{% csrf_token %}` reads the token straight off the context, so an isolated context would render the tag to nothing and produce a form that answers 403 on submit -- silently, because a missing hidden input looks like no input at all. The `only` discipline belongs to the pure partials under `templates/partials/pure/`, which take a declared set of values and read nothing else; this one is portal-local and shares its page's context deliberately. A plain multipart POST and a native file input, with no script of any kind. There is deliberately no progress bar: the browser already draws one for a form submission, and the alternative is an upload path that stops working the moment scripting does -- on the one boundary in this product that row-level security is enforcing, and for the one action a client most needs to succeed. The accepted types are a recommendation and the control says so, because the SERVER does not restrict them. Writing "aceitamos apenas PDF" would be a promise nothing keeps. The size limit is the opposite: it IS enforced, the figure comes from the same setting the endpoint checks, and a test moves that setting to prove the sentence follows it. String literals inside a tag that sits within an HTML attribute are single-quoted throughout this project. The class-token scanner reads attributes with a regex, so a double quote inside one ends the attribute early and feeds the tag's own words to the stale-stylesheet guard as though they were class names. {% endcomment %}
