{% load i18n ptbr %}{% comment %} The twelve-month DAS strip, rendered from context alone so that the dashboard and a client's detail page draw the same calendar rather than two that drift apart. Context: calendar -- CalendarCell rows, already read from the Obligation table. Empty renders the explicit "nothing generated" line, never a blank grid: a strip that silently draws nothing looks the same on a morning the scheduler failed as on a client with no rows yet. calendar_client -- the client the strip is about, named above it. Absent draws no caption at all, for a page that already says whose calendar this is somewhere above. calendar_client_linked -- opt in to making that name a link into the client's workspace. Off by default, and the default is the important half: the client detail screen includes this same strip, and there the caption names the very client whose page the reader is already standing on. A link there leads nowhere and reads as a promise the product does not keep. The dashboard, whose strip is about whichever client the filter selected, turns it on. The flag travels on the include tag, so neither view had to grow a context key and the detail screen stays untouched. The id is what the dashboard's filter swaps by selector -- its target, its select and its outerHTML swap all name #calendario-strip -- so the id belongs to the element rather than to the page including it, and both callers get it for free. **The indentation below is absolute, not relative, and it is load-bearing.** Django's include tag emits a partial's text verbatim: only the first line inherits the caller's indentation, and every following line carries whatever this file spells.
