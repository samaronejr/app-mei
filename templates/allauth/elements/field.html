{% load allauth %}{% comment %} One allauth control, in this project's field styling. Reads `attrs`, never a BoundField, and that is forced rather than chosen. allauth calls this element with loose keyword arguments and frequently with no form behind it at all — the address-change screen renders the current address as a disabled text control, and the TOTP enrolment screen renders the shared secret the same way. So this file cannot delegate to `partials/pure/field.html`, which takes a BoundField; it mirrors the attribute set the upstream element reads, and only the markup changes. `fields.html` beside it takes the other road. It is handed a real form, so it delegates every control to the project partial and inherits the whole accessibility contract — the error summary, the anchored links, the described-by chain — rather than restating it here. Between them the two cover every screen allauth ships. Three shapes, chosen by type: a textarea, a checkbox or radio with its label after the control, and everything else with its label before. The branch picks the opening tag; each control then carries its own class literal, because Tailwind compiles only the names it can read in this file and a value assembled at render time has no rule. The label is always rendered and always visible, bound by `for` to the same id the control carries. A placeholder is not a label — it vanishes on the first keystroke, which is exactly when a person most needs to re-read it. THE DESCRIBED-BY CHAIN, restated here rather than borrowed. `partials/pure/field.html` builds one from a BoundField's help text and errors. This element cannot delegate to it — it has no BoundField — so the same chain is built from the slots and attributes it does have, in the same four shapes: help, error, both, or the attribute omitted entirely. Never emitted empty, because an empty value points at no element and reads to assistive technology as a broken reference. The ids are derived from the control's own id, so a caller that passes none simply gets no chain rather than a dangling one. Without it a help slot renders as text that happens to sit nearby: sighted users associate it by proximity, and a screen reader announces the control with no description at all. The TOTP screens are where that matters most, because what to type — six digits, from the app, regenerated every thirty seconds — is not deducible from a label reading "code". `inputmode` is passed through for the same population. It changes nothing on a desktop and swaps a phone's keyboard to the numeric pad, which is the difference between typing a rotating six-digit code in one attempt and typing it twice. {% endcomment %}
