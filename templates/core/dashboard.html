{% comment %} hx-sync drops an in-flight request the moment a newer one starts. A hand moving down the client list faster than the network answers produces overlapping GETs whose responses land in whatever order the wire settles on, and the last to arrive wins the strip -- so the calendar would end up showing a client the accountant had already moved off. The indicator is named by selector and lives in the form, not in the strip: #calendario-strip is replaced outerHTML, so an element inside it is destroyed by the very swap it exists to report on. It is visual only -- static/js/app.js already announces the swap through the one live region this layout owns, and a second region here would say the same news twice. The select is written out rather than passed through partials/pure/field.html: that partial reads a Django BoundField, and this filter is a bare query parameter the view resolves itself. It carries the three classes the partial emits, so the two render identically, and it owes neither aria-invalid nor an aria-describedby chain because it has no error and no help line. The noscript submit is the whole point of the form element. hx-trigger is JavaScript; without it nothing sends the selection, and the accountant is stuck on whichever client the view picked. {% endcomment %}
