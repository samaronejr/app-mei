Reached on both hosts at the identical path, so nothing here resolves a capability, reads a firm-side table or reverses a name `apps/portal/urls.py` does not mount. Upstream branches twice on webauthn — an alternative-options block and a security-key button. `MFA_SUPPORTED_TYPES` lists totp and recovery codes only, so both branches are statically false here and neither is carried over; shipping them would mean markup no test can reach and Tailwind would still have to compile classes for. THE CODE FIELD ACCEPTS A RECOVERY CODE TOO. `BaseAuthenticateForm.clean_code` walks every authenticator on the account and asks each to validate what was typed, so one control accepts both a rotating six-digit code and a stored recovery code. Upstream's label says only "Code" and nothing on the screen mentions the second possibility — which is precisely the screen someone reads when they have lost the phone and are looking for a way in. The help text says it, and is wired to the control through the described-by chain rather than left as nearby prose. `inputmode` is numeric rather than absent because the overwhelmingly common case is the six digits; a recovery code can still be pasted or typed on the symbol keyboard. THE WAY OUT IS A POST, AND IT IS THE ONLY WAY OUT. Between password and code the session is a half-authenticated stage: the ordinary navigation does not exist yet and the browser's back button returns to a form that will not help. Upstream solves it with a second form posting to logout, and that is kept — GET-based sign-out would let any third-party image tag end the stage for the visitor.
