Upstream climbs `mfa/totp/base.html` then `mfa/base_manage.html` then `allauth/layouts/manage.html`, and all three land on the one shell this project ships, so naming it once keeps the chain the extends walk in `tests/ui/test_auth_templates.py` follows down to a single hop. BOTH ENROLMENT ROUTES ARE OFFERED, WHICH IS THE POINT OF THE SCREEN. A QR code alone assumes a second device with a camera pointed at the first. Someone enrolling on a desktop with the authenticator on that same desktop — or on a phone reading this page — cannot photograph the screen they are reading, so the shared secret is rendered beside the image as text they can select and paste. It is READONLY and not disabled. Upstream disables it, and a disabled control is removed from the tab order and cannot be focused, which means the one route that exists for people without a camera is unreachable from the keyboard: you can see the secret and you cannot copy it. Readonly keeps it focusable and selectable while still refusing edits. It carries no name, so it is not posted back with the form. The code control is built from the bound field rather than named by hand — `html_name`, `auto_id`, `errors` — so a rename upstream cannot leave a control that looks right and posts nothing. It is the keyboard-critical input on the page: `one-time-code` lets a phone offer the code from its own clipboard or SMS, `inputmode` swaps the keyboard to the numeric pad, and the help slot is wired to the control through the described-by chain the field element builds, because "code" alone does not say six digits, from the app, changing every thirty seconds. The submitted code is deliberately NOT echoed back on a failed attempt. It has already expired by the time the page returns, so re-displaying it only invites the reader to press Enter again on a value that cannot work. {% endcomment %} {% block head_title %}{% translate "Ativar autenticador" %}{% endblock head_title %} {% block content %} {% element h1 %} {% translate "Ativar autenticador" %} {% endelement %}
