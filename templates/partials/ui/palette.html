{% load i18n %}{% comment %} The command palette: `Ctrl/Cmd+K` opens a native modal holding one combobox whose results are server-rendered (S5.6, AXR1-021). The field asks `/busca/` through HTMX as the user types (`input changed`, 250 ms debounce, a newer keystroke replacing an older request) and the answer -- core/search_results_listbox.html -- is swapped into #palette-results. Arrow keys move aria-activedescendant through the options while focus stays in the field; Enter or a click follows the option. All of it is the `palette` component in static/js/app.js; nothing here is an expression, and no tenant value is written into an x-* or hx-* attribute. The results region is marked data-swap-keeps-focus so the shared after-swap focus handler leaves the caret where the user is typing; the polite status line below the field says that the list changed. Without script there is no shortcut and no palette to open: the dialog never shows, and the visible header search form does the same search as a page. {% endcomment %}
