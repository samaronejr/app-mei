Context (from base.html, not from a view): r1_shell -- an `apps.core.navigation.ProductShell`: the wordmark, the firm's name and the destinations this account may reach, already capability-filtered by `visible_nav_items`. request -- for the active-item marker and the signed-in address. The wordmark is `settings.PRODUCT_NAME`, never a literal: the customer-facing name stays "app-mei" until the name is cleared (plan OD-01), and flipping it is a setting, not a template edit. The navigation holds the MEI-era bar's contract (tests/ui/test_shell.py): one native disclosure that the browser opens and closes, one nav landmark inside it, and the current page marked -- so it still works when no bundle loads. At `md` the disclosure is held open by the stylesheet and reads as a row. The toast region lives here, permanent and empty at load, because a live region announces changes made after it exists; see `partials/ui/toast.html`. The search form is the visible, script-free way into the same search the `Ctrl/Cmd+K` palette runs (S5.6, AXR1-021): a plain GET to the results page. It and the palette are drawn only when `r1_shell.searchable` -- the account may reach the client registry, the capability the search endpoint requires -- so no one is offered a control that refuses them. With the field in the bar, the signed-in address is shown from `2xl` only, so Sair stays on the first row at desktop widths. {% endcomment %}
